MagiTrickle
=======

## Назначение

MagiTrickle (произносится как *Мэджитрикл*) – утилита для точечной маршрутизации сетевого трафика по заданным доменным именам. Представляет собой установочный пакет, устанавливаемый в дополнение к операционной системе маршрутизатора.

<p align="center">
  <img src="https://gitlab.com/magitrickle/magitrickle/-/raw/develop/img/main_screenshot.png" alt="MagiTrickle Screenshot"/>
</p>

Принцип работы основан на подмене основного DNS-сервера через промежуточный компонент без его отключения. Это позволяет перехватывать входящие DNS-запросы, кешировать ответы и сопоставлять IP-адреса с доменными именами. Благодаря этому становится возможной маршрутизация трафика без необходимости очистки DNS-кэша на стороне клиентов. Очистка кэша требуется только при запуске или перезапуске сервиса MagiTrickle, поскольку в этот момент кэш ещё не прогрет, и маршрутизация невозможна до первого запроса к нужному домену.

## Форк WeirdPhrog: приоритет Groups

**Включённые Groups имеют приоритет над Subscriptions**, в том числе когда IP домена из группы входит в широкую подсеть/ASN из подписки. Сначала применяются метки подписок, затем группы могут их переопределить. Приоритет сохраняется при обновлении подписок, редактировании/переключении групп и восстановлении firewall; работает для IPv4 и IPv6. Формат конфигурации не изменён.

Внутри Groups и внутри Subscriptions прежний порядок обработки сохранён. Выключенная группа не перехватывает трафик. Если её VPN недоступен, сохраняется прежнее поведение MagiTrickle: blackhole, а не переход на VPN подписки.

Маршрутизация по-прежнему работает по IP, полученным через DNS роутера. После запуска/перезапуска нужен новый DNS-запрос к домену. Домены с общим IP нельзя независимо развести по разным VPN этим механизмом; приоритет группы распространяется на совпавший IP. Проверяйте результат на новых соединениях.

## Установка из этого форка: Keenetic / Netcraze / Entware

На официальной KeeneticOS/NetcrazeOS сначала должен быть установлен **Entware**. Команда выполняется от root в его Linux-оболочке (обычно SSH-порт 222), а не в командной строке Keenetic/Netcraze на порту 22. Архитектура пакета определяется автоматически через `opkg`, для Keenetic/Netcraze выбирается вариант `_kn`.

Установка или переход с оригинального MagiTrickle одной командой:

```sh
wget -O /tmp/magitrickle-install.sh https://github.com/WeirdPhrog/MagiTrickle/releases/latest/download/install.sh && sh /tmp/magitrickle-install.sh
```

Установщик скачивает пакет только из [релизов WeirdPhrog/MagiTrickle](https://github.com/WeirdPhrog/MagiTrickle/releases), проверяет SHA-256, устанавливает зависимости через Entware и перезапускает сервис. Существующий `config.yaml` сохраняется; перед обновлением создаётся архив состояния и настроек в `/opt/var/backups/magitrickle/`. Настройки Groups и Subscriptions повторно вводить не нужно.

Веб-интерфейс при настройках по умолчанию: `http://IP_РОУТЕРА:8080`. При обновлении адрес/порт остаются из вашей конфигурации.

### Дальнейшие обновления

```sh
magitrickle-update --check    # только проверить доступную версию
magitrickle-update            # установить последний готовый релиз этого форка
```

Используется установленная команда `/opt/bin/magitrickle-update`. Пакет помечается `hold`, чтобы обычный `opkg upgrade` не заменил его оригиналом. Обновлять MagiTrickle следует именно этой командой; она снимает hold на время установки и возвращает его после неё. Другие пакеты обновляются штатно. Фоновое автоматическое обновление на роутере не включается.

Для возврата к конкретному опубликованному релизу:

```sh
magitrickle-update --version ГОД.МЕСЯЦ.ДЕНЬ.НОМЕР
```

Версия указывается без `v` и без `-1`, как в имени релиза. Автоматическое понижение версии запрещено; явный `--version` разрешает его. Конфигурацию при необходимости можно восстановить из сохранённого архива. Удаление пакета: `opkg flag ok magitrickle && opkg remove magitrickle`.

### Сборка будущих релизов

Каждый push в `develop` запускает [GitHub Actions](https://github.com/WeirdPhrog/MagiTrickle/actions/workflows/build.yml): тесты backend с race detector, регрессионные тесты, проверку реальных IPv4/IPv6-пакетов в отдельных Linux network namespaces на iptables legacy/nft, тесты установщика, проверку и сборку интерфейса, сборку семи вариантов Entware.

Только после успеха всех проверок публикуется полный релиз `vГОД.МЕСЯЦ.ДЕНЬ.НОМЕР` с пакетами, `VERSION`, `SHA256SUMS` и установщиком. Достаточно встроенного `GITHUB_TOKEN`; собственные `RELEASE_TOKEN` и ключи не нужны. Сборки веток `codex/*` и pull request не публикуются. Можно также запустить workflow вручную.

## OpenWrt

Исходная поддержка OpenWrt сохранена в коде и Makefile. Для его пакетов запустите workflow вручную с `platforms: all`; вместе с Entware будут собраны `.ipk` и `.apk` для конфигураций `config/openwrt`. Установщик выше предназначен для Entware. APK в таких сборках подписан одноразовым ключом сборки и не подключён к доверенному пакетному репозиторию OpenWrt; для штатного распространения APK нужен собственный постоянный ключ и feed.

## Описание типов правил

### Namespace (Именное пространство)

Охватывает указанный домен и все его поддомены.

Например, при записи `example.com` будут обрабатываться:
```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### Wildcard (Подстановочный шаблон)

Шаблон с `*` и `?` — позволяет задавать гибкие условия:
- `*` — любое количество любых символов
- `?` — ровно один любой символ

Например, при записи `*example.com` будут обрабатываться:
```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```

### Domain (Точный домен)

Правило применяется только к строго указанному домену, без поддоменов.

Например, при записи `sub.example.com` будут обрабатываться:
```
❌ example.com
✅ sub.example.com
❌ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### RegExp (Регулярное выражение)

Для опытных пользователей. Используется парсер [dlclark/regexp2](https://github.com/dlclark/regexp2).

Например, при записи `^[a-z]*example\.com$` будут обрабатываться:
```
✅ example.com
❌ sub.example.com
❌ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```
