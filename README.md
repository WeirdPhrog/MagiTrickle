MagiTrickle
=======

## Назначение

MagiTrickle (произносится как *Мэджитрикл*) — утилита для точечной маршрутизации сетевого трафика по заданным доменным именам, IP-адресам и подсетям. Представляет собой установочный пакет, устанавливаемый в дополнение к операционной системе маршрутизатора.

<p align="center">
  <img src="img/main_screenshot.png" alt="Скриншот исходного MagiTrickle"/>
</p>

Скриншот исходного проекта; новые настройки этого форка на нём не показаны.

MagiTrickle обрабатывает DNS-запросы через промежуточный компонент перед основным DNS-сервером роутера, кеширует ответы и сопоставляет IP-адреса с доменными именами. Доменные правила начинают работать после получения соответствующего DNS-ответа. После запуска или перезапуска сервиса может понадобиться новый DNS-запрос; очистка DNS-кэша клиента помогает получить его раньше. Правила для IP-адресов и подсетей от DNS-запросов не зависят. DNS, который клиент отправляет в обход этого компонента, например напрямую через DoH, не наполняет его кеш.

## Форк WeirdPhrog: приоритет Groups

**Включённые Groups имеют приоритет над Subscriptions**, в том числе когда IP домена из группы входит в широкую подсеть/ASN из подписки. Сначала применяются метки подписок, затем группы могут их переопределить. Приоритет сохраняется при обновлении подписок, редактировании/переключении групп и восстановлении firewall; работает для IPv4 и IPv6. Существующие группы и подписки совместимы с форком и сохраняются при обновлении.

Внутри Groups и внутри Subscriptions прежний порядок обработки сохранён. Выключенная группа не перехватывает трафик. Если её VPN недоступен, сохраняется прежнее поведение MagiTrickle: blackhole, а не переход на VPN подписки.

Доменные правила маршрутизируют трафик по IP, полученным через DNS роутера. Домены с общим IP нельзя независимо развести по разным VPN этим механизмом; приоритет группы распространяется на совпавший IP. Проверяйте результат на новых соединениях.

При обработке DNS перебираются только включённые доменные правила: размер списка IP-подсетей/ASN не увеличивает этот перебор. Массовое сохранение правил использует индекс по ID, сохраняя порядок записей. При переподключении VPN маршруты восстанавливаются, даже если шлюз прежний, а интерфейс был пересоздан.

Срок жизни динамического адреса в ipset равен DNS TTL плюс `app.netfilter.ipset.additionalTTL`, с округлением вверх до секунды и ограничением 1–2147483 секунд. Нулевой TTL не создаёт бессрочную запись; статические IP-правила остаются бессрочными.

## Интерфейс загрузки подписок

На странице **Subscriptions / Подписки**, над списком, находится общий выбор **«Интерфейс загрузки»**. Он применяется сразу ко всем подпискам: к загрузке нового URL, ручной синхронизации и обновлению по расписанию. Выбор автоматически сохраняется в `app.subscriptionFetchInterface` в `config.yaml`, действует без перезапуска и сохраняется после обновления приложения. В старых конфигурациях используется системный маршрут.

При выборе VPN сначала весь запрос, включая HTTP-перенаправления, выполняется через этот интерфейс. Если интерфейс отсутствует, отключён или загрузка завершается ошибкой, исходный URL повторно загружается через системный маршрут. Каждой попытке отводится до 15 секунд. Если обе попытки не удались, текущие правила подписки остаются на месте. Возврат к VPN проверяется при следующей загрузке; выбранное значение не сбрасывается.

Запросы к внешнему DNS-серверу также привязаны к интерфейсу. Если системный DNS указывает на сам роутер (например, `127.0.0.1`), запрос передаётся локальному DNS-прокси, который использует собственные настройки upstream. Публичный DNS-сервер автоматически не подставляется. Интерфейс должен иметь рабочую маршрутизацию к источнику подписки.

Поле интерфейса внутри каждой подписки по-прежнему управляет маршрутизацией трафика по её правилам; общий интерфейс загрузки на него не влияет. Это также не меняет приоритет Groups и поведение их VPN. Настройка применяется только к загрузке списков подписок: установщик и `magitrickle-update` используют системную маршрутизацию.

## Установка из этого форка: Keenetic / Netcraze / Entware

На официальной KeeneticOS/NetcrazeOS сначала должен быть установлен **Entware**. Команда выполняется от root в его Linux-оболочке (обычно SSH-порт 222), а не в командной строке Keenetic/Netcraze на порту 22. Архитектура пакета определяется автоматически через `opkg`; для Keenetic/Netcraze выбирается вариант `_kn`, если он предусмотрен для этой архитектуры.

Первая установка, переход с оригинального MagiTrickle или обновление уже установленного форка одной командой:

```sh
opkg update && opkg install curl ca-bundle coreutils-sha256sum && curl -fsSL https://github.com/WeirdPhrog/MagiTrickle/releases/latest/download/install.sh -o /tmp/magitrickle-install.sh && sh /tmp/magitrickle-install.sh
```

Команда сначала устанавливает инструменты HTTPS-загрузки и проверки SHA-256. Установщик скачивает пакет только из [релизов WeirdPhrog/MagiTrickle](https://github.com/WeirdPhrog/MagiTrickle/releases), проверяет SHA-256, устанавливает зависимости приложения через Entware и перезапускает сервис.

**Перед переходом с оригинала удалять MagiTrickle не нужно.** Если в веб-интерфейсе есть несохранённые изменения, сначала нажмите **«Сохранить изменения»**. Установщик сохраняет существующий `/opt/var/lib/magitrickle/config.yaml`; перед заменой пакета создаёт архив состояния и настроек в `/opt/var/backups/magitrickle/`. Настройки Groups и Subscriptions повторно вводить не нужно. После обновления перезагрузите страницу веб-интерфейса.

Веб-интерфейс при настройках по умолчанию: `http://IP_РОУТЕРА:8080`. При обновлении адрес/порт остаются из вашей конфигурации.

### Дальнейшие обновления

```sh
magitrickle-update --check    # только проверить доступную версию
magitrickle-update            # установить последний готовый релиз этого форка
```

Используется установленная команда `/opt/bin/magitrickle-update`; в оригинальной версии её может не быть — тогда используйте полную команду установки выше. Пакет помечается `hold`, чтобы обычный `opkg upgrade` не заменил его оригиналом. Обновлять MagiTrickle следует именно этой командой; она снимает hold на время установки и возвращает его после неё. Другие пакеты обновляются штатно. Фоновое автоматическое обновление приложения на роутере не включается; обновление списков подписок по расписанию продолжает работать.

Для возврата к конкретному опубликованному релизу:

```sh
magitrickle-update --version ГОД.МЕСЯЦ.ДЕНЬ.НОМЕР
```

Версия указывается без `v` и без `-1`: например, для тега `v2026.10.14.11` — `2026.10.14.11`. Автоматическое понижение версии запрещено; явный `--version` разрешает его. Конфигурация сохраняется и при понижении версии; её восстановление из архива выполняется отдельно при необходимости. Удаление пакета: `opkg flag ok magitrickle && opkg remove magitrickle`.

### Сборка будущих релизов

При push в `develop` [GitHub Actions](https://github.com/WeirdPhrog/MagiTrickle/actions/workflows/build.yml) запускает:

- тесты backend с race detector, `go vet` и проверку форматирования;
- замеры обработки больших списков правил и проверки восстановления IPv4/IPv6-маршрутов после пересоздания интерфейса;
- проверку реальных IPv4/IPv6-пакетов на iptables legacy/nft в отдельных Linux network namespaces;
- проверку загрузки подписок через выбранный интерфейс, включая DNS и переход на системный маршрут;
- тесты установщика и ShellCheck;
- проверку и сборку веб-интерфейса, модульные тесты Deno и браузерные тесты Playwright.

После проверок собираются семь вариантов Entware. Коммиты только с документацией могут использовать `[skip ci]`, чтобы не выпускать повторно те же пакеты.

Только после успеха всех проверок и сборок публикуется полный релиз `vГОД.МЕСЯЦ.ДЕНЬ.НОМЕР` с пакетами, `VERSION`, `SHA256SUMS` и установщиком. Достаточно встроенного `GITHUB_TOKEN`; собственные `RELEASE_TOKEN` и ключи не нужны. Сборки веток `codex/*` и pull request не публикуются. Для ручной публикации запустите workflow из ветки `develop`.

Эти проверки выполняются в CI на Linux и не включают установку и работу на физическом роутере, в том числе NETCRAZE ULTRA.

## OpenWrt

Исходная поддержка OpenWrt сохранена в коде и Makefile. Для сборки и публикации его пакетов запустите workflow вручную из ветки `develop` с `platforms: all`; вместе с Entware будут собираться `.ipk` и `.apk` для конфигураций `config/openwrt`. Обычные автоматические проверки и релизы охватывают только сборки Entware. Установщик выше предназначен для Entware. APK в сборках OpenWrt подписан одноразовым ключом сборки и не подключён к доверенному пакетному репозиторию OpenWrt; для штатного распространения APK нужен собственный постоянный ключ и feed.

## Описание типов правил

Доменные правила сопоставляются без учёта регистра. Для обычного домена со всеми поддоменами используйте **Namespace**, для одного точного имени — **Domain**.

### Namespace (Именное пространство)

Охватывает указанный домен и все его поддомены.

Например, при записи `example.com` будут обрабатываться:

```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### Wildcard (Подстановочный шаблон)

Используется [go-wildcard v2.1.0](https://github.com/IGLOU-EU/go-wildcard/tree/v2.1.0) со следующими операторами для ASCII-доменов:

- `*` — ноль или больше любых символов;
- `?` — ноль или один любой символ;
- `.` — ровно один любой символ, включая точку.

Точка в Wildcard не означает строго разделитель доменных уровней: `*example.com` совпадёт также со строкой `exampleXcom`. Если требуется буквальная точка, используйте Namespace/Domain либо RegExp с `\.`.

Например, при записи `*example.com` будут обрабатываться:

```
✅ example.com
✅ sub.example.com
✅ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```

### Domain (Точный домен)

Правило применяется только к строго указанному домену, без поддоменов.

Например, при записи `sub.example.com` будут обрабатываться:

```
❌ example.com
✅ sub.example.com
❌ sub.sub.example.com
❌ anotherexample.com
❌ example.net
```

### RegExp (Регулярное выражение)

Для опытных пользователей. Используется парсер [dlclark/regexp2](https://github.com/dlclark/regexp2). Без якорей выражение может совпадать с частью имени; для полного совпадения используйте `^` и `$`.

Например, при записи `^[a-z]*example\.com$` будут обрабатываться:

```
✅ example.com
❌ sub.example.com
❌ sub.sub.example.com
✅ anotherexample.com
❌ example.net
```

### Subnet / Subnet6 (IP-адрес или подсеть)

Правила IPv4 (`subnet`) и IPv6 (`subnet6`) задаются адресом или сетью в формате CIDR. Например: `192.0.2.10`, `192.0.2.0/24`, `2001:db8::10`, `2001:db8::/32`. Они применяются без предварительного DNS-запроса. Для маршрутизации ASN в подписке нужен список его IP-подсетей; само имя вида `AS12345` не преобразуется в подсети автоматически.
